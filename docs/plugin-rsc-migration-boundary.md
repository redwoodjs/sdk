# plugin-rsc migration boundary

| Area                               | Owner for now                                           | Notes                                                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client-reference discovery canary  | `@vitejs/plugin-rsc` can own this in opt-in canary runs | Required CI stays on the legacy Redwood RSC path until the canary is stable.                                                                                            |
| Required CI RSC path               | Redwood legacy transforms                               | Smoke and playground CI use `RWSDK_LEGACY_RSC_CLIENT_REFERENCES=1` and `RWSDK_LEGACY_RSC_SERVER_REFERENCES=1`.                                                          |
| RSC render manifest boundary       | Redwood                                                 | `renderToRscStream()` still calls `react-server-dom-webpack/server.edge` with Redwood `createClientManifest()`. The plugin-rsc render wrapper remains deferred.         |
| `serverAction()` / `serverQuery()` | Redwood                                                 | Redwood keeps method/origin enforcement, interruptors, response normalization, redirects, errors, metadata, and Worker lifecycle semantics.                             |
| plugin-rsc server references       | Deferred                                                | The plugin-rsc server-reference loader is disabled in the runtime bridge for this slice.                                                                                |
| Dev `$$cache=` ids                 | Redwood adapters                                        | Runtime lookup candidates, manifest/module-map resolution, and client-reference lookup generation normalize plugin-rsc dev cache tags.                                  |
| SSR loading of client references   | Redwood compatibility adapter                           | In plugin-rsc client-reference mode, the SSR virtual lookup returns safe null SSR modules instead of executing browser/client modules.                                  |
| Upstream/API blockers              | Shared                                                  | Manifest metadata, asset/CSS integration, Worker-safe encryption, and Redwood server-function semantics need more upstream/API support or separate implementation work. |
| Planned next slice                 | plugin-rsc client-reference canary hardening            | Keep required CI legacy, run `pnpm test:plugin-rsc-canary` intentionally, and flip one fixture only after repeated green canary runs.                                   |
